# 06. Physical AI PoC 전략 — 디지털 트윈 AI 비주얼 검사관

> 목적: 6개월 뒤 "간단하지만 제가 직접 만든 Physical AI PoC입니다"를 보여줄 수 있는 상태.
> 선택 방향: **인지/검사(고정 카메라)** · 자산 접근 **불확실(토이 병행)** · 역량 **코딩 입문**.

## 0. 한 줄 포지셔닝

> **"디지털트윈팀은 무대(공장)를 만들고, 나는 그 안에서 보고·판단·행동하는 AI를 만든다."**

트윈팀과 경쟁이 아니라 **곱하기** 관계. 그들의 3D 공장을 *지능이 도는 공장*으로 바꿔서,
그들의 결과물 가치를 올리는 동시에 대체 불가능한 자리를 잡는다.
용어는 의도적으로 **"Physical AI"**(NVIDIA Omniverse + Isaac + 합성데이터 + sim-to-real)를 쓴다.

## 1. PoC 정의: AI 비주얼 검사관

비전문가가 1분 안에 이해하고, "AI가 판단했다"가 눈에 보여야 한다.

**루프: 카메라(인지) → 정상/불량 판정(판단) → 알림·리젝트 신호(행동)**

- 불량품이 지나갈 때 화면에 **빨간 박스**가 뜨는 순간 = 판단의 증거.
- 행동(action)은 모션이 아니라 **판정 신호**(pass/fail, 알람, 리젝트)로 충분히 성립.

### 전략의 심장: 합성 데이터
현실 검사 AI의 최대 벽 = **불량 데이터가 없다**(드물고·비싸고·라벨링 고통).
트윈이 있으니 뒤집는다:

> **"트윈 안에서 불량을 무한히 합성해(Isaac Sim Replicator) AI 검사관을 학습시켰습니다."**

- 회장님이 기억하는 문장이 된다.
- 트윈 자산이 "예쁜 3D" → **"데이터 공장"**으로 격상 (트윈팀이 나를 좋아할 이유).
- NVIDIA Physical AI의 교과서 스토리(synthetic data → sim-to-real).

## 2. 기술 스택 (입문자 친화 = "만들기"보다 "조립하기")

| 구성 | 선택 | 이유 |
|------|------|------|
| 환경 | Isaac Sim + 토이 제품/라인 + 고정 카메라 | 실제 USD는 M5 업그레이드 |
| 데이터 | **Isaac Sim Replicator** | 정상/불량 이미지 + 자동 라벨, 조명·각도·위치 랜덤화 |
| 모델 | **이상탐지(Anomaly Detection)** 우선 | 정상 샘플만으로 학습 가능 → 입문자 최적. 대안: 분류기/YOLO |
| 글루 | Python (입문 수준 OK) | 밑바닥 구현 금지, 예제 복사·수정 |
| 연동 | ROS 2 (선택) | 있으면 +1, 없어도 PoC 성립 |

> 모델 라이브러리 팁: 이상탐지는 **Anomalib**(GitHub에서 `anomalib` 검색, Intel) 같은
> 설정 중심 라이브러리를 쓰면 학습/추론을 거의 config로 끝낼 수 있다.
> 객체검출이 필요하면 **Ultralytics YOLO**(https://github.com/ultralytics/ultralytics)가 자료가 가장 많다.

## 3. 6개월 로드맵

| 기간 | 목표 | 산출물 |
|------|------|--------|
| **M1** | Isaac Sim 설치·GUI·USD 감각 (가이드 [01](01-installation.md)~[03](03-usd-structure.md)) | 토이 제품 씬 + 카메라 배치, 이미지 캡처 |
| **M2** | Replicator로 합성 데이터셋 생성(정상/불량, 랜덤화) | 자동 라벨 데이터셋 수백~수천 장 |
| **M3** | 이상탐지 모델 학습 + 추론 | **불량을 빨간 박스로 잡는다** ← 최소 성공선 |
| **M4** | 트윈 카메라 → 모델 → 판정 오버레이로 루프 완성 | 엔드투엔드 데모 1개 |
| **M5** | (선택) 실제 공장 USD 슬라이스 / 실제 카메라 1대 연결, 안정화 | 더 그럴듯한 데모 |
| **M6** | 데모 영상 + 회장님용 1페이지 내러티브 | 발표 패키지 |

**원칙: M3 끝 = 이미 보여줄 게 있는 상태.** 항상 "지금 당장 보여줄 수 있는 버전"을 유지한다.

## 4. 위험과 차단

| 위험 | 차단법 |
|------|--------|
| 트윈 USD 자산 불확실 | **토이 제품 씬으로 시작.** 실제 USD는 블로킹 요인이 아니라 M5 업그레이드 |
| 코딩 입문 | 모델 밑바닥 구현 금지. 설정 중심 라이브러리(Anomalib) + 예제 복사·수정 |
| 시간 제약 | 화려함 금지. **부품 1종 + 불량 1가지**를 끝까지. 범위 확장은 성공 후 |
| RL 토끼굴 | 검사 PoC는 RL 불필요. 유혹되면 M6 이후로 미룬다 |

## 5. 포지셔닝(정치) 무브

- **트윈팀을 아군으로.** "당신들 트윈으로 데이터를 만들어 AI가 돌게 했다"는 그들의 공로를 키운다.
- **점진적 공유.** M3, M4에서 작은 데모를 미리 보여 신뢰를 쌓는다(6개월 침묵 후 한 방 X).
- **언어 통일.** 보고/대화에서 "Physical AI / 합성데이터 / sim-to-real"을 일관되게 사용.
- **1페이지 내러티브 미리 써두기.** 기술이 아니라 *문제→해결→결과* 순서로.

## 6. 회장님용 1페이지 골격 (미리 채워두기)

1. **문제**: 검사 AI는 불량 데이터가 없어서 막힌다 (현실 공통 통증).
2. **착안**: 우리에겐 디지털 트윈이 있다 → 불량을 합성하면 된다.
3. **한 일**: 트윈에서 합성 데이터 생성 → AI 검사관 학습 → 트윈 안에서 실시간 판정.
4. **결과(데모)**: 불량품을 AI가 스스로 잡아내는 30초 영상.
5. **다음**: 실제 라인 카메라/USD로 확장, 품목 추가 → 실제 도입 로드맵.
