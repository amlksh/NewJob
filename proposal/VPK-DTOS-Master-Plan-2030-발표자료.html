Why Now

용역 모델은 구조적으로 한계에 도달했다

  • 매출 = 인력 × 시간 — 성장의 유일한 수단이 채용
  • 프로젝트가 끝나면 노하우는 개인의 머릿속에만 남는다
  • CAE 용역 단가 경쟁은 심화되고, 시니어 의존은 깊어진다
  • 그리고 — AI가 해석 업무 자체를 자동화하기 시작했다

질문은 "자동화가 오는가"가 아니라 "누가 자동화의 공급자가 되는가"다.

Organization

엔지니어를 대체하지 않는다 — 승격시킨다

  • 2026: 플랫폼 TF 4명 (기존 인력 전환 중심)
  • 2027~28: 플랫폼사업부 7~9명 — 용역 수행이 곧 플랫폼 검증
  • 2029~30: Twin별 오너 체계 10명+, Physical AI 전문가 영입
  • 반복 작업 → 플랫폼이 수행
  • 엔지니어 → 판단·승인·지식 자산화 담당
  • 시니어의 노하우 → Playbook·검증 룰로 회사 자산화
  • 새 직무 정체성: "AI를 관리하는 엔지니어"

Risk

리스크는 이미 설계에 반영되어 있다

리스크대응 (아키텍처 원칙으로 동결)
AI가 틀린 결과를 낸다검증된 템플릿만 실행 + 자동 Quality Gate + 사람 승인 없이는 발행 불가
범위 폭주로 실패FMH 하나를 완주한 뒤에만 확장 — Physical AI는 2029 전 착수 금지
플랫폼 고객 확보 지연수익원 5축 분산 — 내부 생산성·정부과제가 먼저 회수
고객 데이터 보안마스킹 게이트웨이 + 온프레미스 LLM 전환 경로(2027)
대형 CAE 벤더 경쟁도구가 아닌 검증된 업무 수행 + 규제 문서 판매 — 다른 시장

Decision

오늘 요청드리는 결정

  • 1. 방향 승인 — "DTOS = VPK의 5년 전환 전략"으로 채택, 본 문서를 기준 문서로 확정
  • 2. 2026 실행 승인 — 현 TF 4명 체제로 FMH Twin MVP 완주 (신규 투자 최소, 하반기 내)
  • 3. 게이트 방식 확대 — 추가 투자는 MVP KPI 실측(판정 일치율·시간 단축) 확인 후 단계 결정

저장소는 하루면 만들지만, 방향에 대한 공감은 하루아침에 만들어지지 않습니다.
DTOS는 프로젝트가 아니라, VPK의 다음 5년입니다.
