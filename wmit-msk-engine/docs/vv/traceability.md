# V&V 추적표

ASME V&V 40 기반. 설계 문서 「OpenSim MSK 시뮬레이션 엔진 개발 프로세스 설계」 §6 을 따른다.

## 1차 COU (Context of Use)

> 설계 초기 단계에서 무릎 임플란트의 하중조건을 추정하는 **참고 도구**.

이 COU 를 전제로 모델 위험도를 낮게 두고, 그에 비례한 신뢰성 활동을 수행한다.
**인허가 제출 근거로 쓰려면 COU 를 재정의하고 V&V 범위를 확대해야 한다.**

### 코드 검증과 기기 결합 검증을 구분한다

V-08·V-09·V-14 는 **코드 검증**이다. 파이프라인이 OpenSim 을 올바르게 부르고,
결합이 의도한 방향으로 동작하는지를 토이 모델로 확인한 것이다.
**이것은 기기 결합이 검증되었다는 뜻이 아니다.**

기기 결합 검증(V-10, V-11)은 실제 기기 파라미터와 실측 데이터가 있어야 하며
**미착수**다. 현재 `configs/devices/` 의 값은 예시값이고, 그것으로 낸 결과는
대외 인용·납품에 쓸 수 없다 (아래 §인용 가부 참조).

V-01 은 이전 판에서 GUI 대조 활동이었다. 토이 회귀 기준선을 V-01 증거로
등재하면서, GUI 대조는 V-13 으로 분리했다. 기존 ID 를 다시 매기지 않기 위해
번호를 새로 부여했다.

### V-13 (GUI 대조) 은 자동화 대상이 아니다

V-13 은 **워크스테이션에서 사람이 OpenSim GUI 를 띄워 수동으로 실행**하고
그 결과를 파이프라인 결과와 대조하는 활동이다. 다음 이유로 자동 테스트에
넣지 않는다.

- GUI 는 헤드리스 서버(`docker/Dockerfile` 기준 환경)에 설치되지 않는다.
  자동화하려면 GUI 가 있는 별도 환경을 CI 에 두어야 하는데, 그 환경이
  기준 실행 환경과 달라지면 대조의 의미가 없어진다.
- 이 활동의 목적은 **엔진이 만든 Setup XML 을 사람이 GUI 로 그대로 열어
  돌릴 수 있는가** 를 확인하는 것이다. 사람이 여는 단계를 자동화하면
  확인하려던 것이 빠진다.

**수행 시점은 B-3(튜닝 trial 정합)** 이다. 토이 모델이 아니라 실데이터·실모델로
대조해야 의미가 있고, B-3 에서 처음으로 그 조합이 갖추어진다.

수행 시 남길 것: 사용한 OpenSim GUI 버전(4.6 이어야 한다 — ADR-0001),
Setup XML 사본, 양쪽 결과 파일, 수치 비교표, 수행자와 수행일.

### 기기 결합 검증 비교기준 후보 (WO-G1 / C-0)

V-10·V-11 은 비교할 기준이 없으면 "검증"이 성립하지 않는다.
**현재 채택된 비교기준은 없다.** 아래는 후보이며, 어느 것도 아직 확인되지
않았다 — 인용하기 전에 원문을 확인하고 이 표를 갱신한다.

| 후보 | 비교 가능한 양 | 한계 | 상태 |
| --- | --- | --- | --- |
| 정상 보행 규준 데이터 (예: Winter, *Biomechanics and Motor Control of Human Movement*) | 무릎 관절각·관절모멘트 | 기기 미착용 기준선일 뿐, 착용 효과의 기준은 아니다 | **원문 확인 필요** |
| 무동력 발목 외골격 보행 연구 (예: Collins, Wiggin & Sawicki, *Nature* 2015) | 보조 토크가 관절 역학에 주는 영향의 방향·크기 | 발목 대상이라 무릎에 그대로 대응하지 않는다 | **원문 확인 필요** |
| OpenSim 기반 보조기기 시뮬레이션 연구 (예: Dembia et al., *PLOS ONE* 2017) | 보조 토크 → 근육력 감소 경향 | 같은 도구·해석 방식이라 방법론 대조에 적합하나, 계측값이 아니라 시뮬레이션 결과다 | **원문 확인 필요** |
| 무릎 보조기·KAFO 착용 보행 연구 | 무릎 ROM·모멘트·근활성 변화 | 1차 Reference Case 에 가장 가깝다 | **문헌 조사 필요 — 후보 미특정** |

> 위 서지사항은 기억에 의존해 적은 것이며 **검증되지 않았다.** 저자·연도·게재지가
> 틀렸을 수 있다. 비교기준으로 채택하려면 원문을 직접 확인하고, 확인자와 확인일을
> 이 표에 적는다. 확인 전 수치를 인용하지 않는다.

선정 기준 (채택 시 만족해야 할 것):

- 무릎을 대상으로 할 것
- 보조 토크의 크기와 관절각·관절모멘트를 **함께** 보고할 것 — 한쪽만 있으면 대조가 안 된다
- 수치가 표·그림 또는 공개 데이터로 제시되어 있을 것
- 대상군(연령·질환·보행 속도)이 명시되어 있을 것 — 적용 한계 판단에 필요하다

채택된 비교기준이 없는 동안 **Device OFF/ON 차이를 정량 수치로 인용하지 않는다.**
상대 경향으로만 표기한다 (WO-G1 §5, C-1 완료조건).

## 적용 한계 (초안)

- 검증 데이터는 **계측형 인공관절을 이식한 고령 피험자의 보행**이다. 정상 무릎, 다른 동작, 다른 연령대로의 외삽은 검증되지 않았다.
- 근육력은 Static Optimization 의 비용함수 가정에 의존한다. EMG 로 확인하지 않았다.
- 개인화 수준은 신장·체중 기반 Scaling 이다. 영상 기반 개인 형상은 반영하지 않는다.
- **V-08 ~ V-11 은 토이 모델 기준이다.** 파이프라인이 OpenSim 을 올바르게
  부르는지와 결합이 역학적으로 작동하는지를 확인한 것이며, 해석 정확도나
  실제 보행 재현을 보인 것이 아니다. 그것은 V-12 의 몫이다.
- **기기 결합 한계** (ADR-0004): 기기는 인체 분절에 강체로 용접된다. 스트랩
  유연성·미끄러짐이 없으므로 전달 토크는 **상한**이다. 기기 내부 부재 하중은
  산출되지 않는다. 힌지 축 어긋남은 각도로 기록하되 그 구속력은 모델에 없다.
- `assistive` 모드의 기기 토크는 Static Optimization 비용함수가 정한 배분
  결과이며, 기기 요구사양이 아니다.

## 재현성

모든 실행은 `runs/<run_id>/provenance.json` 에 OpenSim 버전, Python 버전,
입력 파일 SHA-256, 설정 XML 사본, git commit 을 남긴다.
증거로 인용하는 결과는 반드시 이 기록과 함께 제시한다.

기준 OpenSim 버전은 **4.6 으로 고정**이며 폭이 있는 표기를 쓰지 않는다
(ADR-0001). 회귀 기준선(V-01)도 만들어진 환경을 함께 기록하므로,
수치가 어긋났을 때 버전 변경이 원인인지 바로 구분된다.

## 인용 가부 (citation)

`provenance.json` 과 `results/summary.json` 은 그 실행의 결과를 대외 인용·납품에
쓸 수 있는지를 기록한다.

| 항목 | 의미 |
| --- | --- |
| `citable: false` | 인용 불가. 사유가 `citation_blockers` 에 들어 있다 |
| `citation_blockers: []` | 현재 구현된 검사에서 걸린 사유가 없다 |

현재 검사하는 사유:

- **기기 CAD 출처 미확정** — `source.cad_file` 또는 `source.revision` 이 비었거나
  `TBD` 이면 인용 불가로 기록한다. 어느 리비전의 기기로 낸 수치인지 말할 수
  없으면 증거가 되지 않는다.

> `citable: true` 가 "모든 조건을 만족했다" 는 뜻은 **아니다.** 검사는 해당 WP 가
> 진행되면서 늘어난다 (예: 합격기준 확정 전에는 품질 판정이 `undecided` 로 남는다).
