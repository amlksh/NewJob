# ADR-0002: 1차 Reference 무릎 모델 — 역할 분리에 따른 선정

- 상태: **모델 계열 확정** (WO-G1 / B-0). 구체 모델 파일 확정은 선결-1(모델 라이선스 대장) 이후
- 일자: 2026-09-22 (역할 분리 근거로 재작성 2026-09-22)
- 결정자: VPK PLM기술팀 / WMIT 공동

> **재작성 경위**: 이전 판은 "JAM 을 넣으면 P2 가 1~2개월 늘어난다", "G1 지연
> 위험이 크다" 처럼 **일정**을 근거로 삼았다. 일정은 모델 선정의 근거가 될 수
> 없다 — 일정이 바뀌면 결론도 바뀌어야 하기 때문이다. 이 판은 **역할 분리**를
> 근거로 다시 쓴다. 일정 기반 서술은 전부 삭제했다.

## 배경

이 과제에서 OpenSim 과 SIMULIA(Abaqus)는 **담당하는 물리가 다르다.**

| 영역 | 담당 | 산출물 |
| --- | --- | --- |
| 근골격 동역학 | **OpenSim (본 저장소)** | 관절가동범위, 관절 모멘트, 근육력, 관절반력 |
| 임플란트 응력·변형 | SIMULIA | 부재 응력, 변형 |
| 연조직 변형 | SIMULIA | 연부조직 거동 |
| 상세 접촉 | SIMULIA | 접촉압, 접촉면적 |
| 피로 | SIMULIA | 수명 평가 |

OpenSim 쪽 산출물은 그 자체가 목적이면서, 동시에 **SIMULIA 해석의 경계조건**이
된다. 따라서 OpenSim 에서 정해야 할 것은 "그 경계조건을 신뢰할 수 있게 내주는
모델이 무엇인가" 이지, "어디까지 상세하게 볼 수 있는가" 가 아니다.

## 결정

**Rajagopal 계열 전신 근골격 모델을 1차 Reference 모델 계열로 확정한다.**

근거는 역할 분리다.

- Rajagopal 계열이 내는 양(관절각, 관절 모멘트, 근육력, 관절반력)이
  **OpenSim 담당 영역과 정확히 일치한다.** 더도 덜도 아니다.
- 이 양들이 SIMULIA 로 넘어가는 경계조건이다. 관절반력을 경골(tibia)
  좌표계로 남기는 규칙(CLAUDE.md §4)이 그 인계를 위한 준비다.
- 표준 워크플로(Scale → IK → ID → SO → JR)가 그대로 적용되어,
  코드 검증(같은 Setup XML 을 GUI 로 재현)이 가능하다.

### OpenSim-JAM (Lenhart2015 + COMAK) 을 1차 경로에 넣지 않는 이유

JAM 이 추가로 내주는 것은 **인대력과 연골 접촉압**이다. 이는 위 표에서
**연조직 변형과 상세 접촉**에 해당하며, **SIMULIA 담당 영역이다.**

즉 JAM 을 1차 경로에 넣는 것은 계산 비용이나 일정의 문제가 아니라
**역할 경계를 넘는 일**이다. 같은 물리량을 두 도구가 각자 내놓으면

- 어느 값을 정본으로 삼을지 정해야 하고,
- 두 결과가 다를 때 판정 근거가 없으며,
- V&V 를 양쪽에 각각 해야 한다.

접촉압은 FE 에서 더 정확히 얻는다. OpenSim 은 그 FE 해석이 필요로 하는
하중 조건을 내주는 데 집중한다.

## 영향

- `configs/cases/` 의 `model_file` 과 `required_markers` 는 Rajagopal 계열
  마커셋 기준으로 채운다.
- V&V 추적표의 QoI 는 관절반력·관절 모멘트·근육력·ROM 네 가지로 유지한다.
  인대력·접촉압 QoI 는 이 저장소에 추가하지 않는다.
- **`poc/jam/` 의 존재 이유가 이 결정과 충돌한다.** JAM 호환성 시험은
  역할 경계 밖의 물리량을 OpenSim 에서 내보려는 시도이므로, 계속할 근거가
  약하다. 처리 방침은 아래 미해결 항목으로 둔다 — 임의로 삭제하지 않는다.

## 미해결

- [ ] **구체 모델 파일 확정** — 어느 Rajagopal 판본을 쓸지는 `models/` 반입
      조건(라이선스 대장)이 풀린 뒤 정한다. **선결-1 사항이며 이 ADR 에서
      앞서 정하지 않는다.**
- [ ] `poc/jam/` 을 폐기할지, 참고 자료로 남길지 — 역할 경계상 1차 경로에는
      들어가지 않는다는 점은 위에서 확정했다. 디렉터리 처리 방침만 미정.
- [ ] Rajagopal 계열 모델의 무릎 자유도 표현이 1차 QoI 에 충분한지 확인
      (검증 활동으로 다룬다 — `docs/vv/traceability.md`)
