# ADR-0001: OpenSim 기준 버전을 4.6 으로 고정한다

- 상태: **확정** (WO-G1 / B-0)
- 일자: 2026-09-22 (확정 2026-09-22)
- 결정자: VPK PLM기술팀 / WMIT 공동

## 배경

서버에서 헤드리스로 돌릴 OpenSim 버전을 정해야 한다.
버전이 달라지면 같은 입력에서도 결과 수치가 달라질 수 있고, 그때마다 V&V 를
다시 해야 한다. 따라서 **하나의 정확한 버전**을 고정한다.

## 결정

**기준 버전은 OpenSim 4.6 이며, PyPI wheel 로 설치한다.**

"4.x", "4.6 이상", "최신 4 계열" 같은 **폭이 있는 표기는 쓰지 않는다.**
마이너 버전이 다르면 다른 구성이며, 이 저장소의 V&V 증거는 4.6 에만 적용된다.

근거:

- 4.6 부터 공식 PyPI 패키지가 제공되며, Linux(glibc 2.27+ / x86-64) wheel 이
  Python 3.11–3.13 으로 배포된다. 컨테이너 구성이 한 줄로 끝난다.
- 라이선스는 Apache 2.0 으로 상업적·정부과제 이용에 제약이 없다
  (모델·플러그인은 각자 라이선스를 따른다 — `docs/license_register.md`).

### 검토했으나 채택하지 않은 것 (종결)

이 항목들은 **재논의 대상이 아니다.** 되돌리려면 이 ADR 을 대체하는 새 ADR 이
필요하다.

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 4.5 | PyPI 패키지 없음(Conda 전용). Moco 포함 Conda 패키지는 Windows 한정이라 Linux 서버 배포에 맞지 않는다 |
| 소스 빌드 | 빌드·유지보수 부담이 크고, 재현 가능한 바이너리를 따로 관리해야 한다 |

## 고정 방식

버전은 세 곳에서 정확히 일치해야 한다. 하나라도 어긋나면 재현이 깨진다.

| 위치 | 내용 |
| --- | --- |
| `pyproject.toml` | `opensim==4.6` (범위 지정자 금지) |
| `docker/Dockerfile` | 기준 실행 환경 — python:3.11-slim-bookworm (glibc 2.36) |
| `tests/baselines/*.json` | 회귀 기준선이 만들어진 환경으로 `opensim: "4.6"` 을 기록 |

실행 결과의 `provenance.json` 에도 실제 사용된 OpenSim 버전이 남는다.
결과를 증거로 인용할 때 이 값이 4.6 인지 먼저 확인한다.

## 영향

- 실행 환경 기준은 `docker/Dockerfile` 이다. 로컬 결과와 컨테이너 결과가
  다르면 컨테이너가 정답이다.
- WMIT 서버 OS 가 구형이어도 컨테이너로 격리되므로 영향받지 않는다.
- **버전을 올리면** V&V 활동 V-01 ~ V-05 를 재수행하고, 토이 회귀 기준선을
  `scripts/refresh_toy_baseline.py` 로 다시 만들어 수치 변화를 검토한다.
  기준선이 환경을 함께 기록하므로, 수치가 어긋났을 때 버전 변경이 원인인지
  바로 구분된다.

## 미해결

- [ ] WMIT 서버에서 컨테이너 실행이 허용되는지 (P0)

> OpenSim-JAM 포크의 4.6 호환성은 이 ADR 의 미해결 항목에서 제외했다.
> JAM 이 내는 인대력·연골 접촉압은 역할 분리상 SIMULIA 담당 영역이므로
> OpenSim 기준 버전 결정과 묶을 사안이 아니다 (ADR-0002).
