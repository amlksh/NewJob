# ADR-0004: 인체-의료기기 결합 방식

- 상태: **제안** (P1 구현 완료, G1 에서 확정)
- 일자: 2026-09-22
- 결정자: TBD (VPK PLM기술팀 / WMIT 공동)

## 배경

무릎 재활 보조기를 착용한 상태의 해석을 하려면 기기를 인체 모델에 붙여야 한다.
붙이는 방식에 따라 얻을 수 있는 결과와 해석 비용이 크게 달라진다.

1차 목표는 **착용이 관절 모멘트·근육력·관절반력에 주는 영향**을 보는 것이다.
기기 내부 부재의 응력은 FE(Abaqus) 쪽 일이며 1차 범위가 아니다.

## 선택지

| 선택지 | 방식 | 얻는 것 | 비용·위험 |
| --- | --- | --- | --- |
| **Tier 1** | 기기 강체를 인체 분절에 **용접**하고, 구동은 인체 좌표에 작용하는 액추에이터로 표현 | 질량·관성 효과, 구동 토크 분담, ROM 제한, QoI 4종 전부 | 기기 내부 하중 못 구함, 축 어긋남의 구속력 표현 안 됨 |
| **Tier 2** | 기기를 자기 자유도를 가진 사슬로 만들고 인체와 구속조건으로 연결 | 위 + 기기 내부 하중, 축 어긋남 효과 | **닫힌 운동 사슬**이 생겨 ID/SO 가 구속 문제로 바뀜. 수렴·검증 부담 큼 |
| 외력만 | 기기를 외력/외부 모멘트로만 표현 | 구현 간단 | 질량·관성 효과 누락, 재활 보조기 평가로 부적절 |

## 결정

**Tier 1 을 P1 에 구현하고, Tier 2 는 기기 내부 하중이 필요해질 때 이 ADR 을 갱신하고 간다.**

근거:

- 1차 QoI(ROM, 관절 모멘트, 근육력, 관절반력)는 Tier 1 로 전부 나온다.
  통합 테스트에서 장치 착용 시 근육력이 줄고 장치가 하중을 나눠 받는 것을
  확인했다 (`tests/test_device_integration.py`).
- Tier 2 는 인체와 기기가 두 곳 이상에서 붙으면서 닫힌 사슬을 만든다.
  OpenSim 에서 닫힌 사슬은 구속조건으로 풀어야 하고, Inverse Dynamics 와
  Static Optimization 이 모두 구속을 동반한 문제가 된다. G1 일정 안에
  검증까지 끝낼 수 있다고 보기 어렵다.
- 기기 내부 하중은 어차피 FE 에서 더 정확히 얻는다. Tier 1 이 내주는
  관절반력·부착부 하중이 그 FE 해석의 경계조건이 된다.

## 구현

- 기기 정의는 `configs/devices/*.yaml`, 스키마는 `src/msk_engine/device/spec.py`,
  모델 조립은 `src/msk_engine/device/builder.py`.
- 파이프라인 순서: **Scale → Device → IK → ID → SO → JR**.
  기기는 스케일링 **다음**에 붙는다. 기기 치수는 CAD 로 고정되어 있으므로
  피험자 신장에 맞춰 늘리면 안 된다.
- 기기가 붙은 모델은 `runs/<run_id>/results/device_model.osim` 으로 저장되고,
  IK 이후 모든 단계가 이 모델을 쓴다 (`@ANALYSIS_MODEL@`).

| 기기 파라미터 | OpenSim 표현 |
| --- | --- |
| 질량·관성·질량중심 | `Body` |
| 부착점·자세 | `WeldJoint` (host body 좌표계 기준) |
| 가동범위(ROM) | `CoordinateLimitForce` (회전 좌표에서 **deg** 단위) |
| 보조 토크 (assistive) | `CoordinateActuator`, `optimal_force = max_torque_nm` |
| 지정 토크 (prescribed_torque) | `CoordinateActuator` + `PrescribedController` + `GCVSpline` |
| 수동 강성·감쇠 (passive) | `SpringGeneralizedForce` |
| 힌지 축 | 새 자유도를 만들지 않음. 인체 관절 축과의 **정합성 점검**에만 사용 |

## 적용 한계

결과를 인용할 때 함께 말해야 한다.

- **스트랩은 완전 강체로 본다.** 유연성·미끄러짐·연부조직 압박은 없다.
  실제 착용에서는 기기가 분절에 대해 조금 움직이며, 그만큼 전달 토크가 줄어든다.
  Tier 1 결과는 이 손실이 없는 **상한**으로 읽어야 한다.
- **기기 내부 부재 하중은 나오지 않는다.** 커프·힌지·프레임의 응력은 Tier 2
  또는 FE 해석의 몫이다.
- **힌지 축 어긋남의 구속력은 표현되지 않는다.** 어긋남은 각도로 계산해
  경고로 남기지만(`hinge_misalignment_deg`), 그로 인한 내외반 모멘트나
  피부 전단은 모델에 없다. 허용 오차를 넘으면 그 해석의 적용 범위가 좁아진다.
- **assistive 모드의 장치 토크는 '기기 요구사양' 이 아니라 최적화 결과다.**
  Static Optimization 의 비용함수(활성도 제곱합)가 근육과 장치에 하중을
  어떻게 나눌지 정한다. 모델의 예비(reserve) 액추에이터가 강하면 장치 대신
  예비가 하중을 받아 기기 효과가 작아 보인다. 예비 액추에이터를 약하게 두는
  것이 전제다.

## Abaqus 연계 (범위 밖)

**이 ADR 은 Abaqus 연계를 다루지 않으며, P1 에서 구현하지 않는다.**
관절반력과 기기 부착부 하중이 FE 경계조건이 된다는 것까지가 합의 사항이고,
연계는 별도 모듈과 별도 ADR 로 다룬다. `src/msk_engine/device/` 에 FE 관련
코드를 넣지 않는다. 관절반력을 경골(tibia) 좌표계로 남기는 것(CLAUDE.md §4)이
그 연계를 위한 준비다.
