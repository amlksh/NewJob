# 의료기기 파라미터 회신 요청 — 발송 패키지 (WO-G1 / A-1)

> **이 문서는 발송용 초안이다.** 아래 〔 〕 칸을 채워 의료기기·보조기 측에
> 보낸다. 발송 자체는 사람이 한다.
>
> - 수신: 〔기기 제조사·담당자〕
> - 발신: 〔VPK PLM기술팀 담당자〕
> - 발송일: 〔YYYY-MM-DD〕
> - **회신 희망: 〔W6 시작 전〕** — 사유는 아래 "회신 시점" 참조

---

## 1. 요청 취지

WMIT 통합플랫폼에 구축 중인 근골격(MSK) 해석 엔진에 귀사 기기를 결합해,
착용 상태의 **관절가동범위·관절모멘트·근육력·관절반력**을 산출하려 합니다.

요청드리는 것은 **CAD 원본 형상이 아니라 해석용 파라미터**입니다.

```
CAD  →  Device Parameter  →  OpenSim Device 다물체 모델
```

형상 파일을 유한요소처럼 쓰려는 것이 아니므로 STEP/IGES 원본은 필요하지 않습니다.
아래 표의 물리량만 주시면 됩니다. 기기 내부 부재의 응력·피로 해석은 별도 도구
(SIMULIA)가 담당하며 이 요청 범위가 아닙니다.

## 2. 회신 시점 — W6 시작 전

기기 통합모델 작업(WP-C1)이 이 회신에 종속됩니다. 회신이 늦어지면 그만큼
통합모델 일정이 밀리고, 1차 판정 일정에 직접 영향을 줍니다.

| 항목 | 시점 |
| --- | --- |
| 본 요청 발송 | W1 |
| **회신 희망** | **W6 시작 전** |
| 기기 통합모델 (C-1) | W6–W8 |
| 1차 판정 | W9 |

값이 일부만 확정된 상태여도 **확정된 것부터 먼저** 보내주시면 그 범위에서
작업을 시작할 수 있습니다. 미정 항목은 빈칸으로 두고 알려주십시오.

## 3. 회신물

1. **`device_parameter_template.yaml`** — 같은 폴더의 템플릿. 밑줄 `_` 칸을 값으로 바꿔 회신
2. **부착 위치 회신표** (§5) — 해부 랜드마크 기준 위치
3. **별도 회신 항목** (§6) — 링크 구성, CPM 모드 사용 여부

## 4. 요청 항목

| 항목 | 단위 | 템플릿 위치 | 비고 |
| --- | --- | --- | --- |
| Joint / Joint Axis | 단위법선 | `hinge.axis` | **기준 좌표계를 반드시 밝혀주십시오.** 영벡터는 거절됩니다 |
| ROM | deg | `rom.min_deg`, `rom.max_deg` | 굴곡·신전 한계. **환자 처방 범위가 아니라 기기 스토퍼의 물리적 한계** |
| ROM 스토퍼 강성 | N·m/deg | `rom.stiffness_nm_per_deg` | 0 은 거절됩니다 — 아무것도 막지 못하는 스토퍼가 되므로 |
| Link | — | §6 별도 회신 | 링크 구성과 연결 순서. 현재 모델이 소비하지 않습니다 (사유는 §6) |
| Mass | kg | `segments[].mass_kg` | 0 은 거절됩니다 |
| Inertia | kg·m² | `segments[].inertia` | **질량중심 기준.** 조립체 원점 기준이면 평행축 정리로 옮겨주십시오 |
| Attachment Point | m | §5 회신표 | 대퇴·하퇴 각각, **해부 랜드마크 대비 위치** |
| Actuator | — | `actuation.mode` | 구동 방식과 제어 범위 |
| Prescribed Motion | deg/s | §6 별도 회신 | CPM 등 관절각 강제 모드 사용 여부. **템플릿에 적지 마십시오** (사유는 §7) |
| Assistance Torque | N·m | `actuation.max_torque_nm` | 프로파일과 최대 토크. 연속 정격인지 최대 정격인지 `source.notes` 에 밝혀주십시오 |
| Passive Stiffness | N·m/rad | `actuation.stiffness_nm_per_rad` | 0 은 거절됩니다 |
| **CAD revision** | — | `source.revision` | **TBD 로 회신되면 추적 불가로 처리되어 그 결과를 인용할 수 없습니다** |

### 0 과 TBD 를 거절하는 이유

해석 엔진이 형식만 보고 통과시키면, 빠진 값이 "기기 없음" 과 구분되지 않는
결과를 만들어냅니다. 질량 0 인 기기는 관절 모멘트에 아무 영향을 주지 않고,
강성 0 인 스토퍼는 가동범위를 전혀 제한하지 않습니다. 겉으로는 해석이
성공한 것처럼 보이므로 더 위험합니다.

`source.revision` 이 비어 있거나 `TBD` 이면 결과 파일에 자동으로
`citable: false` 와 그 사유가 기록됩니다. 해석은 돌아가지만 대외 보고·납품에
쓸 수 없는 결과가 됩니다.

## 5. 부착 위치 회신표

템플릿의 `attachment.location` 은 **인체 모델 좌표계** 값이라 기기 측에서
채우실 수 없습니다. 그 칸은 비워두시고(`[VPK]` 표시), 아래 표에 **해부
랜드마크 기준**으로 적어주십시오. 모델 좌표계로의 변환은 VPK 가 합니다.

| 부착부 | 기준 랜드마크 | 랜드마크로부터의 거리 | 둘레 방향 위치 | 비고 |
| --- | --- | --- | --- | --- |
| 대퇴 커프 | 〔예: 대퇴골 외측상과〕 | 〔 〕 mm, 〔근위/원위〕 | 〔예: 전면 중앙〕 | |
| 하퇴 커프 | 〔예: 경골 조면〕 | 〔 〕 mm, 〔근위/원위〕 | | |
| 힌지 중심 | 〔예: 대퇴골 외측상과〕 | 〔 〕 mm | | |

착용 위치가 환자 체형에 따라 달라진다면, **기준 체형과 허용 범위**를 함께
적어주십시오. 그 범위가 해석 결과의 적용 한계가 됩니다.

## 6. 별도로 회신할 항목 (템플릿에 넣지 마십시오)

두 항목은 현재 해석 모델이 받지 않습니다. 템플릿에 적으면 파일이 거절되므로
**본문이나 첨부로 따로** 알려주십시오. 받는 이유는 향후 모델 확장 판단에
필요하기 때문입니다.

### (a) 링크 구성과 연결 순서

현재 결합 방식(Tier 1)은 기기 부품을 인체 분절에 고정된 것으로 보므로,
링크 사슬을 모델이 소비하지 않습니다. 그래도 구성을 알아야 Tier 2 승격이
필요한지 판단할 수 있습니다. 간단한 도식이나 설명이면 충분합니다.

### (b) CPM 등 관절각 강제 모드 사용 여부

- [ ] 해당 없음 — 보조 토크만 제공
- [ ] **CPM 등 관절각을 강제로 구동하는 모드가 있음** → 각도 프로파일과 속도(deg/s) 첨부

체크되면 범위 변경 사유가 됩니다 (§7).

## 7. 함께 알려드리는 두 가지

### (1) 현재 결합 방식은 Tier 1 입니다

| | Tier 1 (현재) | Tier 2 (확장 시) |
| --- | --- | --- |
| 결합 | 기기 부품을 인체 분절에 **고정** | 기기가 **자체 자유도**를 가지고 대퇴·하퇴 두 곳에 연결 |
| 자유도 | 늘지 않음 | 닫힌 운동사슬이 생김 |
| 얻는 것 | 질량·관성 효과, 보조 토크 분담, 가동범위 제한 | 위 + **기기 내부 부재 하중** |
| 비용 | 표준 해석으로 처리 | 구속조건 동반 해석. 검증 부담이 커짐 |

Tier 1 의 한계상 아래는 현재 산출되지 않습니다.

- 기기 내부 부재(커프·힌지·프레임)에 걸리는 하중
- 스트랩의 유연성·미끄러짐 (완전 고정으로 가정 → 전달 토크는 **상한**입니다)
- 힌지 축이 해부학적 축과 어긋날 때 생기는 구속력 (어긋난 각도는 기록되나 힘은 모델에 없음)

근거와 적용 한계는 `docs/decisions/ADR-0004-device-coupling.md` 에 있습니다.

### (2) `prescribed_motion` 은 현재 거절됩니다

관절각을 강제로 끌고 가는 구동(CPM 방식)은 현재 엔진이 받지 않습니다.
인체 관절각은 동작 계측에서 역기구학으로 구하는데, 기기가 같은 각도를
강제하면 두 값이 충돌하기 때문입니다.

**귀사 기기에 CPM 모드가 있다면 이것이 Tier 2 승격 사유가 됩니다.**
그 경우 기기가 자체 자유도를 갖는 모델로 바꿔야 하며, 통합모델 작업(C-1)의
범위가 달라집니다. 그래서 §6(b)에서 여부를 여쭙습니다.

## 8. 문의

파라미터 정의·단위·좌표계 관련 문의는 〔담당자·연락처〕로 주십시오.
스키마 상세 설명은 `docs/interfaces/cad_device_parameters.md` 에 있습니다.

### 인수인계 점검 (VPK 내부용 — 발송 시 이 절은 삭제)

회신을 받으면 `configs/devices/` 에 반영하기 전에 확인한다.

- [ ] 길이 단위가 m 인가 (CAD 기본은 대개 mm)
- [ ] 관성이 질량중심 기준인가
- [ ] `source.revision` 이 실제 리비전인가 (`TBD`·`_` 아님)
- [ ] ROM 이 기기 스토퍼 값인가 (환자 처방 ROM 과 구분)
- [ ] `max_torque_nm` 이 연속 정격인지 최대 정격인지 명시되었는가
- [ ] 부착 위치 회신표가 랜드마크 기준으로 채워졌는가
- [ ] CPM 여부 회신을 받았는가 — 해당되면 ADR-0004 갱신 및 C-1 범위 재검토
- [ ] 반영 후 `python scripts/run_poc.py --case ... --dry-run` 으로 검증 통과 확인
